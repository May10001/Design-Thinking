# LangChain 会话代理 — 核心代码讲解

## 整体架构

```
用户输入 → Prompt模板(系统提示+历史+当前问题) → DeepSeek大模型 → 回复
                ↑                                    |
                └──── 历史管理器(自动注入) ←──────────┘
```

核心链路只有一行：`chain = prompt | llm`，然后被 `RunnableWithMessageHistory` 包裹，实现"自动携带历史记录"的对话能力。

---

## 一、大模型接入 — `ChatOpenAI` 指向 DeepSeek

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="deepseek-chat",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com",
    temperature=0.7,
    max_tokens=2048,
)
```

**为什么要用 `ChatOpenAI` 而不是专门的 DeepSeek 类？**

DeepSeek 的 API 协议与 OpenAI 完全兼容（都是 `/v1/chat/completions` 端点，相同的请求/响应 JSON 结构）。因此 LangChain 的 `ChatOpenAI` 只需改 `base_url` 就能直接对接 DeepSeek，无需额外适配器。

| 参数 | 作用 |
|---|---|
| `model` | DeepSeek 的聊天模型名 |
| `base_url` | 把请求从 `api.openai.com` 改发到 `api.deepseek.com` |
| `temperature` | 0~2，越高回复越随机，越低越确定 |
| `max_tokens` | 单次回复最大长度，防止超长消耗 |

`api_key` 从 `.env` 文件加载，不硬编码在代码里——这是安全底线。

## 二、提示模板 — `ChatPromptTemplate` + `MessagesPlaceholder`

```python
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个友好、活泼的猫娘AI助手……"),
    MessagesPlaceholder(variable_name="history"),
    ("human", "{input}"),
])
```

**三条消息的角色：**

1. **`("system", ...)`** — 系统提示，定义 AI 的人设、行为规则、回答格式。这是 prompt engineering 的主战场。
2. **`MessagesPlaceholder(variable_name="history")`** — 占位符，运行时被替换成之前的对话记录列表。不写死内容，因为每次请求历史都不一样。
3. **`("human", "{input}")`** — 用户当前说的话，`{input}` 是变量，调用时动态填入。

**最终发给模型的真实消息长这样（假设历史有2条）：**

```
SystemMessage: "你是一个猫娘……"
HumanMessage:   "你好"           ← 历史第1轮(用户)
AIMessage:      "你好喵！"       ← 历史第1轮(AI)
HumanMessage:   "今天天气怎样"   ← 历史第2轮(用户)
AIMessage:      "阳光明媚喵！"   ← 历史第2轮(AI)
HumanMessage:   "讲个笑话"       ← 当前用户输入 ← 这就是{input}
```

模型看到了完整上下文，所以能给出连贯的回复。这就是"上下文感知"的本质——**把聊天记录直接拼进 prompt**。

## 三、LCEL 管道 — `prompt | llm`

```python
chain = prompt | llm
```

`|` 是 LangChain 的 LCEL（LangChain Expression Language）管道操作符。数据流向：

```
{input: "你好"}
    │
    ▼
prompt.invoke()      → 格式化成 ChatPromptValue(一系列消息对象)
    │
    ▼
llm.invoke(消息)     → 调用 DeepSeek API
    │
    ▼
AIMessage(content="你好喵！")   ← 最终输出
```

`prompt | llm` 等价于一个函数：接收 dict，返回 AIMessage。它本身是一个 `Runnable` 对象，可以继续用 `|` 拼接更多步骤（比如输出解析器），也可以被装饰器包裹。

## 四、历史管理 — `RunnableWithMessageHistory`

```python
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_core.chat_history import InMemoryChatMessageHistory

store: dict[str, InMemoryChatMessageHistory] = {}  # 按 session 隔离

def get_session_history(session_id: str):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

agent = RunnableWithMessageHistory(
    chain,                    # ① 被包裹的链(prompt | llm)
    get_session_history,      # ② 历史获取函数
    input_messages_key="input",   # ③ 用户输入映射到哪个变量
    history_messages_key="history", # ④ 历史映射到哪个占位符
)
```

**调用方式：**

```python
config = {"configurable": {"session_id": "default"}}
response = agent.invoke({"input": "你好"}, config=config)
```

**一次调用的完整流程：**

```
agent.invoke({"input": "你好"}, config)
    │
    ├─ 1. 用 config 中的 session_id 调用 get_session_history
    │      → 拿到该会话的历史列表（可能是空的或已有的）
    │
    ├─ 2. 将 input_messages_key("input") 的值 "你好" 
    │      → 注入到 prompt 的 {input} 变量
    │     将历史列表 → 注入到 prompt 的 {history} 占位符
    │
    ├─ 3. 调用 chain.invoke() → 得到 AI 回复
    │
    ├─ 4. 自动把本轮 (用户消息 + AI回复) 追加到历史记录
    │
    └─ 5. 返回 AIMessage
```

**关键设计：** `input_messages_key` 和 `history_messages_key` 是桥接参数，告诉 `RunnableWithMessageHistory`："入参 dict 里哪个字段是用户输入？prompt 里哪个占位符放历史？" 这样你不必手动操作历史列表——每次调用自动读取、自动追加。

---

## 五、会话隔离 — `store` 字典

```python
store: dict[str, InMemoryChatMessageHistory] = {}
```

不同 `session_id` 对应独立的 `InMemoryChatMessageHistory` 实例，互不干扰。多用户/多会话场景下只需换 `session_id` 即可。

> **注意：** `InMemoryChatMessageHistory` 存在内存里，进程重启即丢失。生产环境可换成 `RedisChatMessageHistory` 或其他持久化实现，只需改 `get_session_history` 内部实现——上层代码完全不用动。

---

## 六、总结：一张图看懂调用链

```
agent.invoke({"input": "你好"}, {"configurable": {"session_id": "s1"}})
    │
    ▼
get_session_history("s1")  ──→  [历史消息列表]
    │
    ▼
prompt 填充:
    system  → 猫娘人设
    history → [之前的对话...]
    human   → "你好"
    │
    ▼
llm.invoke(messages)  ──→  DeepSeek API  ──→  AIMessage("你好喵！")
    │
    ▼
历史自动更新: [...之前的对话, HumanMessage("你好"), AIMessage("你好喵！")]
    │
    ▼
return AIMessage("你好喵！")
```

这五个概念——**LLM 接入、Prompt 模板、LCEL 管道、历史管理器、会话隔离**——就是 LangChain 会话代理的骨架。理解了它们，就理解了代码的 90%。
